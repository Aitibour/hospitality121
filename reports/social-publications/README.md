# Hospitality121 daily X publication

The active local Codex heartbeat is `hospitality121-daily-x-news-and-article`, attached to the existing website chat. The owner authorised unattended posting and selected Vancouver time. LinkedIn is explicitly skipped.

| Vancouver time | Publication |
| --- | --- |
| 09:00 | Recent RSS hospitality technology news, original operational context, source attribution and CTA, with a unique attached image. |
| 13:00 | Summary of a different verified live Hospitality121 article, CTA and unique attached image. The canonical full-article URL goes in the account's first reply. |

The heartbeat checks hourly on the hour and gates publication using `America/Vancouver`, so daylight-saving changes do not shift the intended local hours. Scheduling initiates work; research, image preparation and publishing can take additional time. Only one main post per slot/date is allowed. Missed past slots are not backfilled.

This uses the authenticated browser as no X publishing API credentials are configured. The computer must remain awake, Codex running and X signed in. Browser login expiration or publishing restrictions require account access to be restored. This is a desktop schedule, not a Netlify background job.

Read `ledger.json` and actual recent account posts before publishing. Record main-post success immediately, before its article-link reply, to avoid duplicates after interruption. Retain source evidence, image file/hash, canonical post/reply URLs and proof screenshots. The historical site announcement used a link preview; the new daily format requires actual image attachments.

Use recent RSS discovery rather than copying publisher articles. Verify original reporting and material claims; do not treat the legacy social drafts as fact-checked. Use original illustrations or rights-cleared images, relevant alt text and varied visual compositions. Stop and report missing evidence, images or account access rather than posting filler.
